
# 🚀 Шаг 1: Подготовка ОС, установка Docker и cri-dockerd

Раз уж ты полностью пересоздаешь виртуалки, давай сделаем этот шаг максимально чистым. Нам нужно настроить Docker и CRI-прослойку на **ВСЕХ пяти нодах** кластера (`master-01..03`, `worker-01..02`).

### 1. Установка Docker Engine

Выполни на каждой машине для удаления старых пакетов (если они были) и чистой установки Docker:

```bash
# Обновление системы и установка зависимостей
sudo dnf update -y
sudo dnf install -y dnf-plugins-core nano wget

# Добавление официального репозитория Docker
sudo dnf config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo

# Установка Docker компонентов
sudo dnf install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

```

### 2. Настройка Docker Daemon (Cgroup + Insecure Registry)

Создай/отрейдактируй файл `/etc/docker/daemon.json` на всех нодах:

```json
{
  "exec-opts": ["native.cgroupdriver=systemd"],
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "100m",
    "max-file": "3"
  },
  "insecure-registries": [
    "students.pandora-ad.develop",
    "students.pandora-ad.develop:ВНИМАНИЕ_ПОДСТАВЬ_СЮДА_HTTP_PORT_INGRESS",
    "students-pkgcache.pandora-ad.develop",
    "students-pkgcache.pandora-ad.develop:ВНИМАНИЕ_ПОДСТАВЬ_СЮДА_HTTP_PORT_INGRESS"
  ],
  "registry-mirrors": [
    "http://students-pkgcache.pandora-ad.develop:ВНИМАНИЕ_ПОДСТАВЬ_СЮДА_HTTP_PORT_INGRESS"
  ]
}

```

Запусти и включи службу Docker:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now docker

```

### 3. Установка cri-dockerd (Мост между K8s и Docker)

Выполни на **каждой** ноде:

```bash
# 1. Очищаем старые проблемные файлы
sudo rm -f /etc/systemd/system/cri-docker.*
cd /tmp

# 2. Скачиваем архив и ставим бинарник (без опасных масок rm -rf)
wget https://github.com/Mirantis/cri-dockerd/releases/download/v0.3.15/cri-dockerd-0.3.15.amd64.tgz
tar -xvf cri-dockerd-0.3.15.amd64.tgz
sudo install -o root -g root -m 0755 cri-dockerd/cri-dockerd /usr/local/bin/cri-dockerd
rm -rf cri-dockerd-0.3.15.amd64.tgz cri-dockerd/

# 3. Скачиваем systemd конфигурацию НАПРЯМУЮ в целевую папку от root
sudo curl -sSL https://raw.githubusercontent.com/Mirantis/cri-dockerd/master/packaging/systemd/cri-docker.socket -o /etc/systemd/system/cri-docker.socket
sudo curl -sSL https://raw.githubusercontent.com/Mirantis/cri-dockerd/master/packaging/systemd/cri-docker.service -o /etc/systemd/system/cri-docker.service

# 4. Выставляем жесткие правильные права и сбрасываем контекст SELinux
sudo chown root:root /etc/systemd/system/cri-docker.*
sudo chmod 644 /etc/systemd/system/cri-docker.*
sudo restorecon -v /etc/systemd/system/cri-docker.*

# 5. Правим путь к бинарнику
sudo sed -i 's|/usr/bin/cri-dockerd|/usr/local/bin/cri-dockerd|g' /etc/systemd/system/cri-docker.service

# 6. Перезапускаем systemd и активируем сокет
sudo systemctl daemon-reload
sudo systemctl enable --now cri-docker.socket cri-docker.service
```

### 4. Проверка готовности сокета

```bash
ls -la /var/run/cri-dockerd.sock
# Ты должен увидеть Unix-сокет. Именно этот путь мы будем скармливать kubeadm!

```

### Скрипт автоматизации `install-k8s-docker.sh`

## Шаг 2.2: Инициализация Первой Мастер-ноды через Docker

Теперь самое главное изменение. Мы вызываем `kubeadm init`, но через флаг `--cri-socket` принудительно переключаем кластер на наш сокет `cri-dockerd`.

**Выполнить ТОЛЬКО на `k8s-master-01`:**

```bash
sudo kubeadm init \
  --apiserver-advertise-address=192.168.77.181 \
  --control-plane-endpoint=192.168.77.180:8443 \
  --pod-network-cidr=10.244.0.0/16 \
  --service-cidr=10.96.0.0/12 \
  --kubernetes-version=v1.34.8 \
  --cri-socket=unix:///var/run/cri-dockerd.sock

```

После успешного завершения сразу настраиваем права для `kubectl` администратора на `master-01`:

```bash
mkdir -p $HOME/.kube
sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown $(id -u):$(id -g) $HOME/.kube/config

```

## 💾 Шаг 4.2: Развертывание Headless-сервиса и StatefulSet

> 🚨 **Важный Middle-лайфхак для NFS:** У официального образа PostgreSQL есть давняя проблема при работе поверх NFS-хранилищ: база пытается выполнить команду `chown` на корень примонтированного диска, NFS сервер блокирует это (даже с `no_root_squash`), и контейнер падает. Чтобы обойти это, мы перенаправим рабочую директорию базы в подпапку через переменную `PGDATA`.

```
#!/bin/bash
set -e

REGISTRY="students.pandora-ad.develop:30080/base"
GITEA_URL="http://students.pandora-ad.develop:30080"

echo " Зеркалирование базовых образов → ${REGISTRY}"

mirror_image() {
    local SOURCE="$1"    # например: golang:1.22-bookworm
    local NAME="$2"      # например: golang
    local TAG="$3"       # например: 1.22

    local TARGET="${REGISTRY}/${NAME}:${TAG}"
    
    # Для официальных образов Docker Hub добавляем префикс NORA и namespace library/
    local NORA_SOURCE="students-pkgcache.pandora-ad.develop:30080/library/${SOURCE}"

    echo "--- ${SOURCE} → ${TARGET} (via NORA) ---"

    # Собираем тонкий образ с OCI-лейблом для автопривязки к репо в Gitea
    docker build --no-cache \
        -t "${TARGET}" \
        -f- . <<EOF
FROM ${NORA_SOURCE}
LABEL org.opencontainers.image.source="${GITEA_URL}/base/${NAME}"
LABEL org.opencontainers.image.title="${NAME}"
LABEL org.opencontainers.image.description="Base image mirror: ${SOURCE}"
EOF

    docker push "${TARGET}"
    echo "✓ ${TARGET}"
    echo ""
}

echo "=== Golang ==="
for ver in 1.22 1.23 1.24 1.25 1.26; do
    mirror_image "golang:${ver}-bookworm" "golang" "${ver}"
done

# Python (slim — SDK + runtime)
echo "=== Python ==="
for ver in 3.11 3.12 3.13 3.14; do
    mirror_image "python:${ver}-slim-bookworm" "python" "${ver}"
done

# Node.js
echo "=== Node.js ==="
for ver in 20 22 24; do
    mirror_image "node:${ver}-bookworm-slim" "node" "${ver}"
done

# Nginx
echo "=== Nginx ==="
mirror_image "nginx:1.28-bookworm" "nginx" "1.28-bookworm"
mirror_image "nginx:1.28-bookworm" "nginx" "latest"

# Debian
echo "=== Debian ==="
mirror_image "debian:13" "debian" "13"
mirror_image "debian:13" "debian" "latest"

# Ubuntu LTS
echo "=== Ubuntu ==="
mirror_image "ubuntu:24.04" "ubuntu" "24.04"
mirror_image "ubuntu:26.04" "ubuntu" "26.04"
```
